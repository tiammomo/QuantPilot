# 新手实操：从零完成第一项研究

这篇教程带你完成一个小练习：研究一个标的，生成看板，检查数据和验收结果，再通过追问做一次改进。不要求先理解 Agent 架构，也不要求先编写 Skill。

练习使用贵州茅台（`600519`）作为明确的 A 股标的示例，不代表推荐投资。所需时间取决于依赖下载、数据源和模型响应，不保证固定几分钟完成。

读完后，你应该能回答三个问题：研究的数据来自哪里，这次任务是否完成，下次出了问题先查哪里。

## 先判断自己从哪一步开始

| 当前情况 | 下一步 |
| --- | --- |
| 还没有本地环境 | 完成[根 README 的快速启动](../../README.md#快速启动)，再回到这里 |
| 页面能打开，但没有模型凭据 | 先做下面的“认识工作台”；配置模型后再提交研究 |
| Web、市场数据和模型已准备好 | 从“创建第一项研究”开始 |
| 已有研究项目 | 在原项目练习检查结果和追问，保留已有记录 |

首次安装只需要先启动 Docker 中的 TimescaleDB 和 Redis。ClickHouse、集中日志、Memory 和 Knowledge 可以在理解基础流程后逐步接入；模型通过官方直连或 ModelPort 提供，仓库的 Compose 不安装模型服务。

## 1. 认识工作台

打开启动终端打印的网址，通常是 `http://localhost:3000`。没有项目时，首页的“继续研究”区域为空是正常状态。

先记住三个入口：

| 页面 | 现在用它做什么 |
| --- | --- |
| 首页 `/` | 输入问题，选择模型和输出方式，开始研究 |
| 项目聊天页 | 查看进度、阅读回复、打开结果，继续同一项研究 |
| 策略平台 `/strategy-platform` | 数据不足时检查标的、覆盖与补数需求 |

稍后再了解 `/skills` 的技能和 `/ops-platform` 的任务状态。第一轮可以暂时跳过评测集、观察池和高级配置。

**这一阶段完成的标志**：你能打开首页并找到输入框、模型选择器，以及“生成看板 / 只做问答”的切换。

## 2. 确认模型与输出方式

“模型”负责理解问题和执行分析；填写 API Key 与选择模型是两件事。输入区显示的模型必须与已经配置的服务对应。

| 你配置了什么 | 页面应选择什么 |
| --- | --- |
| `.env.local` 中的 `DEEPSEEK_API_KEY` | `DeepSeek V4 Flash (Official Direct)` |
| ModelPort 的客户端 Key，且已开通本地 Qwen | `Qwen 3.5 9B (Local Q5_K_M)` |
| ModelPort 的客户端 Key，且已开通 DeepSeek | `DeepSeek V4 Flash (ModelPort)` |

默认模型是经 ModelPort 的 Qwen。只有官方 Key、没有 ModelPort 时，需要手动切到 `Official Direct`；设置一个 Key 不会自动更改已有项目。

然后选择 **生成看板**。本练习需要可检查的页面与交付记录；“只做问答”适用于文本交流，不能用它判断看板是否生成成功。

**这一阶段完成的标志**：你知道当前模型的凭据放在哪里、服务是否已启动，并确认选择了“生成看板”。凭据是否真正有效，以实际模型调用结果为准。

## 3. 创建第一项研究

把下面这段文字粘贴到首页输入框：

```text
分析贵州茅台（600519）最近 120 个交易日的价格趋势、波动和最大回撤。
生成研究看板，展示价格与成交量，并说明指标的计算口径。
标明数据来源、实际起止日期和缺失项；数据不足时明确说明，不补造数值。
```

点击 **开始研究**，系统会准备研究空间、提交问题并进入项目页。这个动作已经包含创建项目，不需要先手动创建文件夹。

这段问题包含四个要素：

| 要素 | 示例中的内容 | 为什么需要 |
| --- | --- | --- |
| 明确标的 | 贵州茅台，代码 `600519` | 减少同名、市场或证券类型歧义 |
| 明确范围 | 最近 120 个交易日 | 交易日不等于自然日，限制取数与比较范围 |
| 明确指标 | 趋势、波动、最大回撤 | 让结果能够逐项核对 |
| 明确交付 | 看板、来源、日期与缺失说明 | 知道最后需要得到什么 |

第一次先保留这个范围。增加标的、财报、回测和自动日报会增加数据依赖，适合在这一项练习通过后逐步尝试。

这几个量化词可以先这样理解：交易日是市场实际开市的日子；波动描述收益变化的幅度，不直接表示涨跌方向；最大回撤描述所选区间内从高点到后续低点的最大跌幅。复权则是调整价格序列，以处理分红、拆分等事件对历史价格比较的影响。具体数值仍要核对实际计算方法和价格口径。

## 4. 等待时看什么

项目会经历规划、数据准备、执行与验证等阶段。阶段名称和耗时以当前任务的实际状态为准；看到页面雏形，并不代表验证已结束。

| 页面状态 | 你可以怎么做 |
| --- | --- |
| 正在规划、取数或生成 | 查看进度与说明，保持当前任务；不必重复提交同一个问题 |
| 等待补充信息 | 回答缺少的标的、时间或范围条件，再继续任务 |
| 规划失败，提示模型或服务不可用 | 检查所选模型、Key 和服务，修复后重试；反复改写问题不能修复服务故障 |
| 排队但迟迟不执行 | 到 `/ops-platform` 看 Worker 与队列；Worker 模式下仅启动 `dev:web` 不会托管 Worker |
| 数据不足或来源失败 | 到策略平台检查当前标的和时间范围，再决定补数、缩小范围或稍后重试 |
| 验证失败或正在修复 | 阅读失败原因，等待修复结果；不能把当前页面当作已完成交付 |

如果离开了项目，可从首页已有研究入口重新打开。刷新后先查看恢复的任务状态，再决定是否重试；重复提交可能产生新的模型调用与任务。

## 5. 检查结果，而不只是看图表

看板生成后，先按下面的清单逐项检查。若某一项无法回答，先追问或排查，不要凭页面外观判断完成。

- [ ] 标的是贵州茅台 `600519`，没有混入其他证券。
- [ ] 实际数据起止时间和样本量可见；不足 120 个交易日时有说明。
- [ ] 能找到数据来源与获取时间，知道是否有延迟。
- [ ] 价格复权方式、波动和回撤的计算范围明确。
- [ ] 缺失字段与不确定性已列出；没有用演示值补齐真实数据。
- [ ] 当前任务的验证与验收结果通过，或明确解释仍未通过的项目。

周末、节假日或源数据延迟时，“最近”不一定等于今天。应核对最近交易日和数据源更新时间，不能只看服务是否在线。

**这一阶段完成的标志**：你能用自己的话说明看板覆盖了哪段数据、主要指标怎么计算、还存在哪些限制，并找到本次任务的验收结果。

### 想进一步核查证据时

普通使用先看项目中的结果、状态和限制说明。需要定位具体问题时，再在项目文件视图或工作空间中查找：

| 文件 | 用来回答什么问题 |
| --- | --- |
| `evidence/sources.json` | 使用了哪些数据源和接口证据？ |
| `evidence/data_quality.json` | 缺失、时效与数据质量有什么限制？ |
| `data_file/final/dashboard-data.json` | 看板实际绑定的数据是什么？ |
| `.data-agent/validation.json` | 构建、数据与交付检查有哪些失败项？ |
| `.data-agent/generation-state.json` | 当前请求处于什么阶段，是否记录了错误？ |

默认工作空间位于 `data/projects/<projectId>/`；自定义了 `PROJECTS_DIR` 时以实际配置为准。早期就失败的任务可能还没有产生全部文件，应先看该任务的阶段和错误，不能要求它已经有完整看板证据。文件合同见[生成工作空间契约](../generated-workspace-contract.md)。

## 6. 在同一项目做一次小改进

第一项任务通过后，在原项目中发送：

```text
保持同一标的和时间范围，增加 MA20、MA60 与成交量图。
说明新增指标是否改变了趋势判断，并保留原有数据来源和缺失说明。
```

完成后重新检查新增指标、数据范围和当前任务的验收结果。不要用上一次通过的报告替代本次检查。

这一步练习的是“只改变一个条件”：保留标的和范围，只增加指标。这样更容易判断结果变化来自哪里，也更容易发现遗漏。

MA20 和 MA60 分别表示 20、60 个交易日的移动平均线。它们帮助观察一段时间的价格变化，不能单独保证后续收益。

还可以做一个两标的练习：

```text
比较沪深300ETF（510300）与中证500ETF（510500）最近 120 个交易日的收益和最大回撤。
使用共同交易日与一致的价格口径，标明实际区间、数据来源和不可比较的缺失项。
```

这属于历史比较，不等于可交易策略，也不等于已经验证了组合回测能力。

## 7. 认识帮助你完成研究的 Skill

打开 `/skills`，搜索 `quant-market-data`。先阅读能力详情、版本与兼容性，再选中练习项目和 **PI Agent**，查看项目的实际安装状态。

初次学习只查看即可。新项目会按平台规则准备所需内置技能，完成本练习不要求你手工安装全部技能。

记住三个不同的动作：

| 动作 | 影响 |
| --- | --- |
| 保存草稿 | 保留编辑内容，还没有激活为发布版 |
| 发布技能 | 校验后激活平台版本；不会自动升级已固定版本的项目 |
| 按项目安装或回退 | 改变所选项目、所选 Agent 的受管技能版本集合 |

准备真正修改技能时，再阅读[技能编写教程](07-skills-authoring.md)。Claude Code / Codex 的目录安装可核验，但外部 Agent 的真实工具运行仍需单独测试。

## 8. 收尾与下次继续

保留项目地址或从首页已有研究入口返回。不需要把整个工作空间复制到源码目录，也不需要把研究数据提交 Git。

停止时，在运行应用的终端按 `Ctrl+C`，再按需执行 `docker compose stop`。下次在仓库根目录运行：

```bash
docker compose up -d --wait timescaledb redis
npm run dev
```

如果额外开启了 ClickHouse 或观测组件，用 `docker compose up -d --wait` 恢复完整组件。停止服务保留本地数据；删数据库卷、删 `data/projects/` 或重置数据库会影响已有研究。

## 卡住时，用这四步描述问题

1. **在哪一步**：启动、提交、规划、取数、生成、验证还是再次打开项目。
2. **看到什么**：已脱敏的错误文字、HTTP 状态码与当前任务阶段。
3. **影响范围**：一个项目失败，还是所有项目和页面都失败。
4. **最小检查**：在另一个终端运行 `npm run doctor`；数据库问题再运行 `npm run db:doctor`。

不要发送完整环境文件、Key 或带凭据的日志。安装与运行检查见[本地启动教程](01-quick-start.md)，按现象定位见[故障排查](../troubleshooting.md)。
